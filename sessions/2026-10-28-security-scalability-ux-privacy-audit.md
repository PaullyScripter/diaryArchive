# Repository-wide security, scalability, UX, and privacy audit

- Request: Review the current codebase and identify changes needed to improve security, scalability, user experience, and privacy.
- Findings: The audit confirmed plaintext private metadata, unbounded encrypted key input, per-request MongoDB revocation reads, unleased search/maintenance work, large inline exports, unsafe mutable-media caching, a logout response bug, broad proxy trust, plaintext browser draft persistence, production Mongo authentication gaps, and documentation/metrics drift.
- Changes: Private tags/emotions are no longer persisted or returned outside encrypted payloads; encrypted diary/master-key fields are bounded and validated; logout reliably clears the cookie; media proxy responses are no-store; revocation checks use Redis with Mongo fallback; search outbox entries use atomic leases; startup full reindex is opt-in; maintenance jobs use Redis leases; uploads, exports, repository pagination, and metrics labels are bounded; plaintext draft persistence was removed; production MongoDB auth and a least-privilege app user were added; Nginx logs go to container stdout/stderr; security/deployment/monitoring docs were reconciled.
- Verification: Backend `python -m pytest -q`: 323 passed. Frontend `npm run typecheck`, `npm run lint`, and `npm test -- --run`: passed; 83 frontend tests passed. `python -m compileall -q app`, `git diff --check`, and production Compose validation with temporary placeholders passed. Ruff was unavailable in the local environment; Docker validation required temporary placeholders and did not start services.
- Git: Pending commit for the hardening implementation and synchronization updates.
- Follow-up: Replace the bounded inline export fallback with a durable asynchronous export worker, add a durable account-deletion workflow, perform a manual device/screen-reader pass, and run dependency audits/load tests in CI or a production-like environment.
